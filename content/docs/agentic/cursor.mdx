Cursor reads `AGENTS.md` from the project root. If you have added the
[instruction block](/docs/agentic/agents-md#the-instruction-block) there, the
agent already knows how to use the specs; skip to
[loading each spec](#load-each-spec-only-where-it-applies).

## Project rules

Project rules live in `.cursor/rules/` and must use the `.mdc` extension. A
plain `.md` file there is ignored. Frontmatter decides when a rule applies:

| Frontmatter | Applied |
|---|---|
| `alwaysApply: true` | In every chat |
| `globs` set | When matching files are in context |
| `description` only | When the agent judges it relevant |
| None of these | Only when you @-mention the rule |

## Load the instructions every time

Without `AGENTS.md`, put the instruction block in an always-applied rule:

```md title=".cursor/rules/domain-specs.mdc"
---
description: How to use the Knowledge Graph domain specs in specs/.
alwaysApply: true
---

<paste the instruction block from the AGENTS.md page here>
```

## Load each spec only where it applies

Add one rule per module. `@specs/appointment.md` attaches the file to the
rule's context, so the spec loads only when matching code does:

```md title=".cursor/rules/spec-appointment.mdc"
---
description: Appointment module spec - booking, rescheduling, cancellation, reminders.
globs: src/scheduling/**
alwaysApply: false
---

Code under src/scheduling implements the appointment module.

@specs/appointment.md
```

## Check it is working

Open a file under the matching path and ask the agent which business rules
apply to it. It should answer with ids from the spec. If it does not, check
that the rule's `globs` matches the file and that the file uses `.mdc`.
