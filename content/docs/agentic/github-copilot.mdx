## Repository-wide: the instruction block

Copilot reads `.github/copilot-instructions.md` for every request in the
repository. Paste the
[instruction block](/docs/agentic/agents-md#the-instruction-block) there:

```md title=".github/copilot-instructions.md"
<paste the instruction block from the AGENTS.md page here>
```

Copilot also reads `AGENTS.md`. If you already keep the instruction block
there, you do not need to copy it.

## Path-specific: which spec applies

Files in `.github/instructions/` ending in `.instructions.md` apply only to
paths matching `applyTo`. Add one per module:

```md title=".github/instructions/spec-appointment.instructions.md"
---
applyTo: "src/scheduling/**"
---

Code under src/scheduling implements the appointment module. Read
specs/appointment.md before changing it, and follow the domain specs
instructions for this repository.
```

Copilot does not inline the spec from an instruction file; the instruction
tells it to open `specs/appointment.md`, which it can do in agent mode, in
code review and as the cloud agent.

## Review pull requests against the specs

Copilot code review uses the same instruction files. With the setup above, ask
for a review on a pull request and it checks the change against the rules for
the paths it touches. Asking explicitly sharpens the result:

```text title="Pull request comment or chat prompt"
Review this change against specs/. Cite the rule id for every violation, and
list behaviour the change adds that the spec does not specify.
```
