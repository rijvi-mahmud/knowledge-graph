## Always loaded: import it in CLAUDE.md

`CLAUDE.md` can import files with `@path`. Paths are relative to the file that
contains the import.

```md title="CLAUDE.md"
## Domain specs

@specs/appointment.md

Follow these rules exactly and cite their ids in commits. Anything the spec
does not list is unspecified: ask instead of inventing it.
```

Imported files load at the start of every session and count against context.
Keep `CLAUDE.md` short and import only the specs the project builds against.

## Loaded on demand: a path-scoped rule

A rule in `.claude/rules/` with a `paths` field loads only when Claude reads or
edits a matching file.

```md title=".claude/rules/appointment-spec.md"
---
paths:
  - "src/scheduling/**/*.{ts,tsx}"
---

Scheduling code implements `specs/appointment.md`. Read it before changing
anything here, follow its rules, and cite rule ids in commits.
```

## Already have AGENTS.md?

Claude Code reads `AGENTS.md` when there is no `CLAUDE.md`. If you have both,
add `@AGENTS.md` to `CLAUDE.md` so one file serves every tool.
